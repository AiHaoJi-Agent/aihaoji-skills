# Ai好记无品牌触发设计

## 目标

用户表达个人笔记、笔记本或当前 Skill 已支持的笔记详情意图时，即使没有提到“Ai好记”品牌，也默认路由到 Ai好记 Skill。用户明确指定本地文件、代码仓库、Obsidian 或其他服务时，服从用户指定的载体。

## 路由优先级

1. 用户明确指定载体时，优先使用该载体，不触发 Ai好记。
2. 未指定载体的个人笔记、笔记本和笔记详情意图，默认触发 Ai好记。
3. 只出现 `notes`、`folder` 等词，但上下文是源码、仓库、接口字段或本地文件操作时，不触发 Ai好记。

## 正向触发范围

- 查询最近、最早或指定关键词的笔记。
- 按标题、关键词或原链接查找笔记。
- 列出、创建、重命名、删除、整理或移动笔记本。
- 整理、移动或自动归类笔记。
- 查看笔记总结、大纲、精华、全文、原文或润色稿。
- 导出笔记，查看划线、高亮、批注、我的记录或 AI 高亮。

以上请求无须包含“Ai好记”“AI好记”或 `aihaoji`。

## 排除范围

- 当前代码仓库、源码、测试或接口实现中的 `notes`、`folder` 等概念。
- 明确要求创建、读取或修改本地 Markdown、文本文件或会议纪要文件。
- 明确指定 Obsidian、Notion、有道云笔记或其他笔记服务。
- 用户明确给出文件路径、仓库路径或其他存储位置。

## 安全边界

- 只读请求可以直接查询 Ai好记开放平台。
- 创建、重命名、移动、删除和自动归类等写操作，必须先查询真实 ID，展示变更计划并等待明确确认。
- 删除笔记本继续要求单独确认。
- 接口失败时不得回退为扫描本地目录或猜测笔记内容。

## 实现范围

- 收紧并补全 `skills/aihaoji/SKILL.md` 的 frontmatter `description`，同时覆盖无品牌正向意图和显式载体排除条件。
- 在 Skill 正文前部增加简短的触发边界和路由优先级，供不完全依赖 frontmatter 的宿主执行。
- 保留现有 API、配置、确认和回读规则，不增加后端能力。
- `SLASH_COMMAND_TOOL_CHAR_BUDGET` 仅作为 Claude Code 本机诊断参数，不作为公开安装要求或 Skill 运行依赖。

## 验证设计

静态契约测试检查：

- 无品牌的笔记、笔记本和详情意图被写入触发规则。
- 代码仓库、本地 Markdown、Obsidian 和其他指定服务被写入排除规则。
- 写操作确认规则没有被弱化。

宿主矩阵至少覆盖：

- T1：`帮我看最近的笔记`。
- T2：`帮我找这个链接对应的笔记：https://example.com/article`，验证无品牌 URL 查找。
- T3：`列出我的笔记本`。
- T4：`帮我找标题包含“测试笔记”的笔记，然后查看大纲、划线和批注`，避免新会话缺少指代上下文。
- T5：`把标题包含“测试笔记”的笔记导出为 Markdown`。
- N1：在代码仓库搜索 `notes` 实现。
- N2：在明确本地路径新建 Markdown 会议纪要。
- N3：在 Obsidian 中管理笔记。
- W1：无品牌创建笔记本请求，确认前不得写入。
- W2：无品牌移动笔记请求，确认前不得写入，确认后要求回读。
- W3：无品牌自动归类请求，必须读取详情和记录、保留待确认项且不得删除笔记本。
- W4：无品牌删除笔记本请求，必须单独确认。

跨平台矩阵只验证路由、误触发和确认边界，不在四个平台重复执行真实写入。重命名、笔记本移动、批量请求字段和完整异常分支由静态契约或模拟请求测试覆盖。

真实集成测试分层：

- R1：使用专用测试授权读取最近笔记，只记录成功、权限和脱敏结论。
- R2：使用专用测试授权验证详情、记录和 Markdown 导出，只记录字段和流程是否可用，不记录正文。
- E1：缺少读取权限时，验证权限提示且不扫描本地目录。
- E2：模拟 `429/5xx`，验证不编造结果、不回退本地搜索。

真实写入只使用可恢复测试数据，并在明确批准后执行；没有相应测试条件时保持未验证。

## 非目标

- 不为不同宿主维护多份 Skill 内容或平台专用触发词。
- 不通过扩大到所有“记录”“文件”“内容”请求来提高触发率。
- 不修改 Claude、OpenClaw 或 Hermes 的模型配置来掩盖 Skill 触发问题。
